# Paper Studio · 使用说明

这是独立的、可组合的论文写作工作台。PaperOrchestra 是初始策略来源之一，不是整套应用依赖。现有绘图模块作为一个模块接入，后续各合作者可以独立替换自己的方法。

## 开始

```powershell
cd paper-studio
npm ci
npm run build
npm start
```

打开 http://localhost:8787/ 。点击右上角“API 设置”管理连接；画板工具栏也有钥匙图标。可配置 OpenRouter、OpenAI 兼容、Gemini 原生和 Anthropic 原生协议，各模块选择自己的连接和模型，文本与图片也能分开接入。服务端 `.local/api-settings.json` 保留连接配置，不回传完整 key 或写入论文导出，兼容已有 `.env.local` OpenRouter 设置。生成会产生相应供应商费用。“测试连接”只读取账户或模型列表，不生成内容，也不验证具体模型能力。操作与边界见 [API 连接说明](API_CONNECTIONS.md)。

1. 点击“新建研究”。三个上传入口分别为论文模板、Idea、Experiment（MD / TXT / CSV / JSON）。模板支持 ZIP，或同时选择主 `.tex` 与 `.sty/.cls` 等文件；已有模板也可以在同一入口只上传缺少的依赖。仅补齐原模板依赖不会使已有章节或候选失效。“载入演示材料”使用随源码附带的合成材料和自编 article 模板，不读取任何私人论文目录，也不是正式会议模板。
2. 左侧是九个模块：规划、引用库、Introduction、Related Work、Method、Experiments、Abstract、Conclusion、图表。
3. 右侧为**当前模块**选择方法与模型。选择方法会保存到该模块；修改连接或模型 ID 后点击“保存配置”。可以配置各章不同的方法和模型，再生成整篇候选。方法有真实执行阶段，并展示来源与边界。
4. 点击“生成整篇候选”：规划 → 多源文献调查 → Method → Experiments → 图表 → Related Work → Introduction → Abstract → Conclusion → 整稿审查与修订。图表与写作可并行；选择旧的仅画板方法时仍需手工提交。章节方法与模型可以独立替换。
5. 生成结果先进入“候选版本”，主稿不变。看差异、候选预览和警告，再接受候选。同一批内容未改动时可逐章接受，剩余章节仍可整批确认；手动修改上游内容后，相关旧候选仍需重新生成。
6. 日后改某一章：修改生成要求、换方法，生成当前模块候选，再接受替换。只替换目标正文，其他章不改；受影响的模块显示“依赖有更新”，由你决定是否同步。
7. 直接修改正文后“保存到主稿”或 Ctrl+S。支持 Markdown、数学公式、表格和 `[@引用键]`。手改不会取消你给该章配置的生成方法。锁定章节阻止 AI 生成/替换，仍允许本人手改。版本历史恢复会新增版本，而不是删除后续记录。

## 绘图

点击“图表与画板”，研究材料自动交给现有 Paper Studio。选择图类型、方法与模型，生成后编辑文字、形状、路径、分组、箭头和布局。在画板顶部点“提交到论文”，填图注；然后返回章节编辑，接受图表候选。

已接受的图会出现在全文预览中，保存的是原生对象文档，不是把 PNG 包进 SVG。可以再次“编辑矢量对象”，或只“修改这张图的图注”。每次修改形成不可变图版本，保留其他图。画板中选择“新建另一张图”可添加第二张图。切换画板会提示未提交编辑可能丢失。

“独立画板（仅导出）”是独立编辑/导出入口；它不提供嵌入画板的直接回传按钮。需要回传主稿时使用工作台内的画板。

默认自动图表方法会从真实材料的表格创建数据绑定统计图；方法图使用三张 Gemini Image 视觉方案进行比较，再生成文本、形状、路径和分组，执行渲染后视觉审查。视觉方案 PNG 不嵌入最终 SVG。中间结果保存在项目 `figure-jobs/`，可恢复已完成的子模块。没有冒充集成 FigTree、AutoFigure-Edit、TikZ 或原生 PPTX。

## 引用与证据

默认引用方法分主题查询 OpenAlex，失败时回退 Crossref，再按真实记录与摘要筛选相关文献。原 Semantic Scholar 方法仍可选择。服务失败不会用模型补造文献；显式跳过检索且引用库为空时保留 TODO。元数据核验不等于全文论据核验。

可在引用模块手动登记、修改真实文献的标题、作者、年份、URL 和证据笔记；引用键保持稳定。手动记录标为“用户提供”，检索记录仅表示元数据来自真实接口，**不表示已核验每个论文论据**。引用库有记录后，概览从结构化库生成，避免手改概览与实际引用对象脱节。

只有 Idea spark，没有实验记录时，可以生成完整章节结构的研究草稿，但 Experiments 明确写 TODO。应用不执行科研实验，也不将其他论文的实验当成你的结果。AI 仍可能遗漏负结果、产生无来源背景判断或夸大因果；审查和提示词都不是事实正确性的保证。

## 导出与合作

- “全文预览”自动编译并直接显示上传模板排版的 PDF，包括已接受主稿的公式、表格、引用和矢量图。支持缩放、选择文字、打开和下载 PDF。保存正文或接受候选后，预览更新；未接受候选不进入 PDF。
- 导出 JSON 是推荐交接方式：材料、各模块配置、候选、历史、引用、原生图对象一起保存；导入创建新项目，不覆盖原项目。它不是实时多人协作或自动跨机器合并。
- Markdown 适合继续写作；BibTeX 保存共享引用库；LaTeX 导出正文源稿。推荐导出“论文源文件 · ZIP”，其中包含 `main.tex`、实际模板样式、引用库和矢量图的 SVG/PDF。单独 `.tex` 不包含这些依赖。
- PDF 使用已有 pdflatex，不自动安装 TeX、字体或宏包；图形先转换为原生矢量 PDF。编译器日志与排版警告保留。相同内容复用已编译 PDF，不调用模型、不产生模型费用。缺少模板样式时明确提示文件名，不切换到通用网页排版。
- 当前 PDF 编译只配置了英文；中文主稿请导出源文件并使用支持中文的 TeX 环境。尚未接入 Word、PPTX 或在线共同编辑。

## 失败、刷新与冲突

已完成候选逐模块保存。网络错误、取消或服务重启后，可以查看候选，整篇任务可“从已保存的候选继续”。恢复要求材料、章节基线、依赖、方法、模型、生成要求和锁定状态没有改变；已接受/拒绝的候选不能作为未完成任务继续。改变设置后开始新任务。

生成时手改目标章节、改材料或依赖章，旧候选不能直接接受，系统保留候选并拒绝覆盖新内容。材料更新只提示已有章节需要同步，不自动重写。

数据保存在 `outputs/papers/<project-id>/project.json`；任务在 `outputs/papers/_runs/`；PDF 快照在项目 `builds/`。这是本机开发版本，默认只监听回环地址，不应不加认证地暴露到公网。

## 代理与模型

Windows 上默认识别用户已启用的回环系统代理，也可设置 `PAPER_PROXY_URL`。需要 Node.js 24.14+；`PAPER_SYSTEM_PROXY=0` 关闭自动识别。启动日志只显示代理地址，不显示 key。OpenRouter 调用元数据与用量保存于 `outputs/usage/openrouter.jsonl`，其他供应商记录在 `outputs/usage/providers.jsonl`；是否支持 reasoning 参数取决于接口和模型。

完整安装、操作、备份与排障手册见 [README.md](../README.md)。独立开发约定见 [MODULE_CONTRACT.md](MODULE_CONTRACT.md)，绘图边界见 [FIGURE_GUIDE.md](FIGURE_GUIDE.md)。历史私人模型验收记录不随源码包发布。
