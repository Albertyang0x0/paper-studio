# Paper Studio

Paper Studio 是一个本地运行的模块化论文写作工作台。输入论文模板、研究想法和实验记录，生成各章节与图表的候选版本；用户审核后写入主稿，也可以直接编辑正文、引用和矢量图。

各模块独立选择方法、API 连接和模型。例如 Introduction 使用一种论证策略，Method 使用另一种写作策略，绘图使用独立的视觉生成与矢量重建流程。项目选择性复用 PaperOrchestra 的提示词，不依赖其演示界面或整套运行程序。

本文面向第一次安装、使用或参与开发的合作者。当前默认方法是可运行的研究基线，不代表已经评估出各模块的最优方法。应用不执行科研实验；材料不足时的论文是带待补项的草稿，不能把生成内容直接当成已验证结论。

## 1. 安装与启动

### 环境要求

| 依赖 | 是否必需 | 用途 |
| --- | --- | --- |
| Node.js 24.14 或更高版本、npm | 必需 | 安装依赖、运行前后端；仓库 `.node-version` 指定 Node 24 |
| 浏览器 | 必需 | 使用工作台 |
| 支持所选模型的 API 账户或本地兼容服务 | AI 生成时必需 | 生成论文、视觉方案、矢量对象和模型审查 |
| 已安装的 `pdflatex` 及模板需要的 TeX 宏包 | PDF 预览时必需 | 按论文模板编译英文论文 |
| Python、Playwright | 日常使用不需要 | 网页回归测试 |
| Git | 源码协作时需要 | 分支、提交和合并 |

没有配置 API 时，仍可导入项目、手动编辑和导出；没有 TeX 时，仍可使用章节编辑与画板，但无法在工作台内编译论文 PDF。应用不会自动安装 TeX、字体或宏包。

### 从源码启动

克隆仓库或解压源码包，进入包含 `package.json` 的 `paper-studio` 根目录。在终端执行：

```sh
node --version
npm ci
npm run build
npm start
```

在浏览器打开 [http://localhost:8787/](http://localhost:8787/)。不要直接双击 `index.html`，也不要使用文件浏览器打开前端源码。

使用期间保持启动终端运行。终端按 `Ctrl+C` 停止服务；以后重新进入同一目录执行 `npm start` 即可，已保存的项目不会因此删除。修改前端源码或更新代码后，需要重新运行 `npm run build`。

PDF 预览前可检查编译器是否可用：

```sh
pdflatex --version
```

若编译器不在 PATH 中，在 `.env.local` 中设置 `PAPER_PDFLATEX` 为其可执行文件的完整路径，然后重启服务。

Windows 上尚未安装 TeX 时，可参考官方 [MiKTeX 安装说明](https://miktex.org/howto/install-miktex)。先在 TeX 环境中安装模板需要的宏包；工作台编译时不会替你安装缺失宏包。安装后重新打开终端，再检查 `pdflatex --version`。

### 开发模式

```sh
npm ci
npm run dev
```

前端通常是 [http://localhost:5173/](http://localhost:5173/)，后端仍是 `8787`。以终端输出的实际地址为准。开发模式会监听源码变化，不要同时启动另一份占用相同端口的正式服务。

默认服务只监听本机回环地址 `127.0.0.1`。这不是已经配置登录、权限和多人实时编辑的公网服务。

## 2. 第一次使用

先用演示材料熟悉候选与主稿的区别，再换自己的研究材料：

1. 打开工作台，点击右上角 **API 设置**，建立文本连接；需要 AI 绘图时再配置图片连接。具体步骤见下一节。
2. 点击 **新建研究 → 载入演示材料**。填写项目名称，点击 **保存研究项目**。示例来自 [examples/demo](examples/demo/README.md)，是合成研究设定与自编 article 模板，没有真实实验结果，也不是会议模板。
3. 在左侧选择 **Introduction**，右侧确认方法、API 连接和模型，点击 **保存配置**，再点击 **生成当前模块候选**。这是一次模型生成，会按供应商规则计费。
4. 查看 **候选版本** 的差异、预览和检查结果。点击 **接受并替换此模块** 后，才会写入主稿；也可选择 **不采用，保留主稿**。
5. 修改主稿中的一句话，点击 **保存到主稿**。在 **版本历史** 查看记录；有 TeX 环境时打开 **全文预览** 查看 PDF。
6. 熟悉操作后，新建正式研究，上传自己的完整模板、Idea 与 Experiment，再使用 **生成整篇候选**。

不想产生模型费用时，可以跳过 API 和生成步骤，载入演示材料后直接手写章节，测试保存、预览和导出。

## 3. 配置 API 与模型

工作台右上角 **API 设置** 与画板工具栏的钥匙图标打开同一个配置窗口。连接是“通过哪个服务访问模型”；方法是“以什么步骤完成任务”。两者可以独立选择。

### 新增连接

1. 点击 **新增连接**，填写连接名称，选择 **接口协议**。
2. 填写服务给出的 Base URL 和 API key。Base URL 是接口根地址，不要附加 `/chat/completions` 等具体调用路径；只向可信服务提交 key。
3. 填写默认文本模型、默认图片模型。使用该服务自己的模型 ID。
4. 可先点击 **测试连接**，再点击 **保存配置**。测试只读取账户或模型列表，不生成论文或图片、不保存未提交配置，也不证明某个模型支持视觉、图片输出或结构化结果。
5. 选择 **默认文本连接**、**默认图片连接**，点击 **保存默认连接**。写作和图片生成可以使用不同供应商。
6. 在各论文模块右侧选择连接和模型，点击 **保存配置**。画板各阶段还可以单独指定连接和模型。

### 支持的协议

| 协议 | 地址形式 | 适用范围 |
| --- | --- | --- |
| OpenRouter | 预设 `https://openrouter.ai/api/v1` | 文本、视觉输入及支持图片输出的模型 |
| OpenAI 兼容 | 服务给出的 `/v1` 根地址，例如 `https://api.openai.com/v1` | Chat Completions；图片可选 Images API 或 Chat Completions 图片输出 |
| Gemini 原生 | 预设 `https://generativelanguage.googleapis.com/v1beta` | 原生文本、视觉输入与支持图片输出的模型 |
| Anthropic 原生 | 预设 `https://api.anthropic.com` | 文本和视觉输入；不能作为图片生成连接 |

选择 **OpenAI 兼容** 后，配置窗口会出现 **图片接口**：按服务实际支持的格式选择 **Images API · 生成 / 参考图编辑** 或 **Chat Completions · 图片输出**，再保存连接。两种格式不是所有兼容服务都支持。

本地 OpenAI 兼容服务可选择无需 key。例如接口可配置为 `http://localhost:11434/v1`，但实际能力取决于本地服务与模型。仅修改 URL 不能自动支持 Azure 专用接口、Bedrock、Vertex AI、OAuth 或其他非兼容协议。

代码中的 Gemini 预设示例是：OpenRouter 使用 `google/gemini-3.1-pro-preview` / `google/gemini-3-pro-image`，原生 Gemini 使用不带 `google/` 前缀的 ID。这是配置预设，不是对模型当前可用性或账户权限的保证；请以所用服务实际支持的 ID 为准。

写作模型需要文本与结构化输出能力。视觉设计与审查模型需要读取图片；生成视觉方案的模型需要真正支持图片输出。不能将普通文字模型填入图片模型字段就视为具备生图能力。

### 密钥与费用

- GUI 设置保存在服务端 `.local/api-settings.json`，重启后保留。文件不加密，不要提交 GitHub 或交给合作者。
- `.env.local` 中的旧 OpenRouter 设置仍兼容；使用 GUI 配置其他服务不需要先填写这份文件。
- 编辑同一个地址、同一种协议的连接时，key 留空表示保留原 key；更换地址或协议必须重新输入对应 key。
- 正常论文与图表导出不包含连接 key。项目 JSON 仍包含研究材料、正文和历史，是研究数据，不应因此当成公开安全文件。
- AI 写作、图片生成、局部重生成和模型审查都可能收费。整篇流程、三张视觉提案与多轮矢量修订包含多次调用，不是一次 API 请求。实际费用取决于模型、输入长度、轮数、失败重试和供应商账单，没有固定的“一篇论文价格”。
- 查看 `outputs/usage/openrouter.jsonl` 或 `outputs/usage/providers.jsonl` 的用量记录。接口未返回实际费用时，记录不能替代账单；当前没有统一的消费上限控制。

完整说明见 [API_CONNECTIONS.md](docs/API_CONNECTIONS.md)。

## 4. 准备三个输入

点击 **新建研究**，或已有项目左侧的 **研究材料**，配置以下三个输入。Idea 与 Experiment 支持上传文本或直接粘贴。

| 输入 | 支持形式 | 作用 |
| --- | --- | --- |
| 论文模板 | `.tex` 与依赖文件，或 `.zip` | 论文 PDF 的字体、页面、标题和其他 LaTeX 排版设置 |
| Idea | `.md`、`.txt`、`.csv`、`.tsv`、`.json` | 研究问题、方案、贡献与方法细节 |
| Experiment | 同 Idea | 实验设置、真实结果、对比、消融和限制 |

Idea 与 Experiment 各使用一个材料入口；上传新文件会替换该角色的旧文件。若有多份记录，先合并为一个有清晰小节的材料文件。单个上传材料不能超过 1 MB。当前入口不是 PDF、Word 或代码仓库解析器。

在 **更多设置** 中选择主稿语言和写作要求。中文可用于章节编辑与生成，但内置论文 PDF 编译目前只配置英文 `pdflatex`。

### 论文模板

建议同时上传主 `.tex` 与相关 `.sty`、`.cls`、`.bst`、`.bib`、`.cfg`、`.def`，或打成一个 ZIP。多份 `.tex` 时，在模板文件列表里确认 **主文件**。

当前约束：最多 80 个文本文件、总量不超过 4 MB；文件名使用英文字母、数字、空格、下划线、点或连字符。ZIP 导入会按文件名展开到同一目录，不能依赖复杂子目录结构或重复文件名；二进制模板图片、字体不会随该入口导入。

只上传会议示例 `.tex`、缺少真正控制排版的 `.sty/.cls`，通常不能得到会议模板的效果。若已有模板缺少依赖，可回到同一入口只上传缺少的样式文件；无需重新生成论文正文。上传新的主 `.tex` 则视为更换模板，请同时带上其依赖。

模板决定排版，不是写作素材。系统保留模板的前导区设置，重新装配各模块正文，不复制其中的示例论文，也不保证沿用特殊章节顺序、附录结构或作者宏。当前导出作者默认为 `Anonymous authors`；最终作者等投稿元信息可在导出的 LaTeX 中调整。

未上传模板时使用默认 article 排版；**载入演示材料** 使用的也不是 NeurIPS、ICLR 或其他正式会议模板。

### Idea 建议内容

不要求固定 schema，但内容越明确，后续越容易审核：

```markdown
# 研究问题
我们解决什么问题，现有方法的局限是什么？

# 核心方法
输入、输出、各模块职责、算法步骤与公式。
区分已经实现的内容与计划中的内容。

# 贡献
列出拟主张的贡献，以及支持它们的证据来源。

# 方法图要求
希望图中出现哪些阶段、实体、信息流和分支？
哪些符号需要统一，哪些关系不能画错？

# 限制与相关工作
已知适用条件、失败情形；已有文献的真实题名或链接。
```

### Experiment 建议内容

```markdown
# 实验设置
数据集、划分、样本量、模型、超参数、种子和评测指标。

# 主结果
填写实际完成的结果表；说明指标方向、单位和统计口径。

# 对比与消融
基线来源、公平对比条件、各消融设置及其真实结果。

# 误差与分析
重复次数、方差/置信区间（若有）、失败案例与负结果。

# 尚未完成
明确列出 TODO，不能用假定数值填补。
```

只有 Idea 也可开始研究草稿，但应用不会替你运行实验。没有提供的结果应保留 TODO，不能补造“完整实验”。如果借用另一篇论文的结果，必须标明来源与用途，不能描述为本项目的测量结果。

最后点击 **保存研究项目**。更新已有材料会提示相关章节需要同步，但不会自动改写已接受主稿。

## 5. 生成和修改论文

### 界面与模块

左侧选择论文模块，中间编辑正文，右侧配置当前模块的方法、模型、生成要求并查看运行记录。四个主视图是 **章节编辑**、**全文预览**、**版本历史**、**矢量画板**。

| 模块 | 用途 |
| --- | --- |
| 论文规划 | 研究叙事、章节结构、文献调查和图表需求 |
| 文献与引用 | 结构化引用库及检索 |
| Introduction / Related Work | 研究动机、贡献与相关工作 |
| Method | 方法、定义、公式和算法描述 |
| Experiments | 实验设置、结果与分析 |
| Abstract / Conclusion | 基于方法和结果形成摘要与结论 |
| 图表与画板 | 图表资产、图注和矢量编辑 |

### 生成整篇

1. 保存材料和未保存的正文编辑。
2. 逐模块检查右侧的方法、连接和模型。模型字段修改后点击 **保存配置**，再切换模块。
3. 点击 **生成整篇候选**。默认执行顺序为：规划 → 文献 → Method → Experiments → 图表 → Related Work → Introduction → Abstract → Conclusion，再做整稿审查与定向修订。默认自动图表方法可与部分正文并行。
4. 查看进度、错误和审查记录。已完成结果逐模块存为候选，生成不会立即覆盖主稿。
5. 审核各章候选及引用、图表。可逐模块 **接受并替换此模块**，或在确认整批内容后点击 **接受整批候选**。
6. 打开 **全文预览**，检查接受后的主稿，而不是未接受候选。

锁定模块不参与整篇自动生成。若选择手动画板方法，图表需要在画板编辑并提交，不能期待该方法自动完成图。需要自行登记引用时可选择 **跳过文献检索**；没有已有引用库就跳过，会留下待补项，而不会获得真实文献。

### 候选和主稿有什么区别

- **主稿**：手动保存或已接受的内容，进入全文 PDF 和论文导出。
- **候选**：新方法、新模型或新修改要求产生的提案；可以预览、比较、编辑、接受或不采用。
- 生成多个候选不会自动把最后一份写入论文。候选警告需要本人核验，模型审查不是事实正确性的保证。

使用 **编辑候选 → 保存候选** 可先修正正文候选，再接受；引用与图表使用各自的结构化编辑界面。同一批未改动的候选可逐章接受，再接受剩余整批，不会仅因同批规划已接受就误判为过期。

### 只替换一个模块：以 Introduction 为例

1. 选择 **Introduction**，先保存当前编辑。
2. 在右侧 **选择方法** 更换策略，选择连接与模型，点击 **保存配置**。
3. 在 **本次修改要求** 填写具体要求，例如：“保留术语与引用，按问题—现有缺口—方法—贡献组织；不要增加材料没有的实验结果。”
4. 点击 **生成当前模块候选**，比较差异并核验论点。
5. 点击 **接受并替换此模块**。新 Introduction 进入主稿；其他章节不会被自动重写。

如果修改 Method、Experiments、规划或引用库影响其他模块，工作台显示依赖更新提示。需要同步哪些章节，由你决定；对那些章节再生成候选并接受。

### 手改、锁定与版本历史

- 在正文编辑区直接输入，点击 **保存到主稿**，或按 `Ctrl+S` / `⌘+S`。未保存文本不会进入预览或导出。
- 支持 Markdown、GFM 表格、行内 `$...$`、块公式 `$$...$$`、引用 `[@key]` 和图引用 `[fig:key]`。引用键和图键必须对应项目中的真实记录。
- **锁定模块** 阻止 AI 生成或候选替换该章，但仍允许本人手动编辑；需要自动修改时先解锁。
- **版本历史 → 恢复此版本** 会新增一个恢复版本，不删除后续记录。恢复上游内容也可能使旧候选的依赖过期。

### 取消、失败与恢复

论文右侧运行记录中点击停止图标（提示 **取消生成**）。停止只针对当前任务，不会删掉主稿或已完成候选；已发出的供应商调用仍可能计费。

整篇任务若仅绘图失败，正文候选仍保留，显示可重试的部分完成状态。点击 **重试未完成模块**；其他中断状态可使用 **从已保存的候选继续**。恢复要求材料、章节基线、方法/模型、生成要求与锁定状态仍相容。修改过这些条件后，请开始新任务，不能强行用旧候选覆盖新内容。

刷新浏览器可以重新连接仍在后台运行的任务；关闭或重启 Node 服务会中断执行，不会自动在后台继续调用模型。

## 6. 引用与证据

默认 **多源文献调查** 从 OpenAlex 检索，失败时回退 Crossref，再做去重与摘要相关性筛选。另有 Semantic Scholar 检索方法可选。API 限流或检索失败不会改用模型编造文献。

手动补充文献：进入 **文献与引用 → 手动登记文献**，填写标题、作者、年份、原文 URL 和摘要/证据笔记，点击 **保存文献**。然后使用库中显示的引用键，在正文写 `[@citation_key]`；不要把 DOI、题名或任意字符串当作已登记的键。

引用概览由结构化库生成，应编辑文献记录而不是手改概览。检索记录的“仅元数据已核验”表示真实接口返回了题名等信息，不表示已经阅读全文或核实该文献支持每个主张；手动记录标为用户提供。投稿前仍需核验原文、作者年份、论据对应和会议引用格式。

## 7. 生成与编辑图表

### 从论文进入画板

进入 **图表与画板** 或顶部 **矢量画板**。已有材料与选定图的原生对象会自动传给画板，不需要重新上传 JSON。已有图可 **编辑矢量对象**；待接受图可 **继续编辑画板候选**。

**独立画板（仅导出）** 或 [http://localhost:8787/figure](http://localhost:8787/figure) 是独立入口，不提供嵌入画板的直接回传按钮。要提交到当前论文，请从该论文的内嵌画板进入。

### 生成一张方法总览图

1. 在画板点击 **生成图表**。
2. 在 **图形与参考** 中选择 **方法总览图**；也可选择系统/模型架构、训练与推理流程、核心机制详解、方法对比图。
3. 填写绘图要求：要表达的科学关系、重点、符号、版面方向和不应出现的内容。不要只写“画得漂亮”。
4. 可上传并选择 0–3 张参考图，每张不超过 4 MB。它们用于布局与视觉语言参考，不提供你的实验事实。公开源码包不包含原工作区的私人参考图。
5. 在 **方法与模型** 选择流程、图片连接/模型、各文本阶段连接/模型及审查轮数。确认视觉阶段能读图、图片模型能生图。
6. 点击 **开始生成**；已有图时是 **重新生成整图**。仅打开窗口或改设置不会执行生成。
7. 查看 **运行记录**。有视觉方案时可切到 **视觉方案** 检查位图提案，再 **返回矢量图** 检查实际重建结果。

默认 **AI 视觉方案 → 保真矢量重建** 的流程为：材料分析 → 三张图片提案与选择 → 拆解背景、节点、文字、连线与插画 → 子代理生成原生元素 → 按坐标组装 → 渲染对照与局部修订。它不是只把用户给定的一张 PNG 转换为 SVG；日常流程先为当前材料设计视觉方案，再重建可编辑版本。

**自由矢量设计（原流程）** 从语义模块规划和设计出发，不以保留图片蓝图的几何布局为目标。材料中有可用真实结果表时，论文自动图表方法还可创建数据绑定统计图；不能从参考图片或想法推断不存在的实验数值。当前没有通用统计分析后端或完整数据表编辑器。

### 画板怎么编辑

| 操作 | 方法 |
| --- | --- |
| 移动、缩放整个模块 | 单击模块，拖动或操作边框 |
| 平移画布视角 | 点击画布后按 ↑ ↓ ← →；按住 Shift 加快移动，点击“适应画板”恢复全图 |
| 编辑模块内部对象 | 双击模块进入内部；从左侧图层选小对象 |
| 修改文字 | 双击文字，或在右侧属性栏修改文本、字号等 |
| 修改形状和配色 | 选择对象，在属性栏改位置、尺寸、填充、描边或渐变 |
| 修改连接线 | 选择箭头，调整颜色、线宽、端点、转折点/曲线控制点；可恢复自动布线 |
| 保留某个对象或模块 | 锁定对象或锁定整个模块；锁定内容在局部重生成中保留 |
| 仅重新生成一个模块 | 选择未锁定模块，展开“重新生成此模块”，填写要求，点击“重生成选中模块” |
| 撤销 / 重做 | `Ctrl+Z` / `Ctrl+Shift+Z`，或工具栏按钮 |
| 收起 / 展开属性栏 | 顶部“属性”按钮；默认固定展开，不随选择自动弹出或隐藏 |

背景分区、标题、文字、插画路径与连接线保存为原生对象，不是整张位图放进 SVG。画板支持直接导入基础 SVG 对象，尚不支持所有 SVG 特性、自由路径节点编辑或原生 PPTX 导出。

### SVG 转为可编辑 JSON（无需模型）

在独立画板或论文内嵌画板点击 **导入 SVG**，选择不超过 5 MiB 的 `.svg` 文件。程序在浏览器中直接解析图形、文字、坐标和样式，转换为现有 `paper-atelier/1` 对象；不调用生成模型，也不需要 API key。导入后从图层选择对象，或双击模块进入内部，修改文字、颜色、位置和大小。点击 **导出 → JSON 可编辑项目** 保存，之后通过 **打开项目** 重新打开。

支持矩形、圆/椭圆、直线、折线、多边形、路径、文字、分组、常规变换、实色、虚线、线性填充渐变及受支持的首尾/中间箭头标记。标准 SVG `DOCTYPE` 文件头只作识别并移除，不下载 DTD 或展开实体；支持 `pt/mm/cm/in/pc` 等物理单位、常见静态 CSS 选择器、`font` 简写、完整字体候选列表和 `!important` 优先级。文字支持已定位的 `tspan`、`letter-spacing` 和单行单对象的 `textLength`；Inkscape `shape-inside` 仅使用文件已有的定位文字，不重新计算自动换行。描边与填充的 `paint-order` 会保留。

本地 `symbol/use` 引用会展开为可独立编辑的实例；保留分组透明度、用户坐标中的单形状裁剪，以及内嵌 PNG/JPEG。矩形上的整幅单图片 `pattern` 会转换为图片和裁剪；样本中的偏移着色阴影、扩边扣除阴影会保留为效果。受支持的悬停 `<set>` 按默认静态外观导入并提示；链接分组移除交互链接，Inkscape 编辑器辅助信息忽略。引用缺失相对图片时，在原位置生成带叉号的占位框并列出路径，不读取本地目录或请求网络；占位框不代表恢复了原图片。从网页单独保存的 SVG 若缺少网页 CSS，程序无法补回其原有样式。

JSON 使用可选的 `assets` 资源表按图片内容去重，图片对象仅保存资源引用和位置、缩放等属性；分组上的 `clip`、`opacity`、`svgShadow` 保存裁剪和效果。画板中的阴影由浏览器按局部对象绘制，导出的 SVG 保留滤镜。图片可整体移动、缩放和旋转，内部像素不会识别成文字或矢量；已经转曲的文字仍是路径。分组会整理为模块；可明确识别的模块间箭头可转换为原生连接线，其余保留为路径。

蒙版、任意滤镜、径向渐变、重复平铺图案、网络图片/字体/引用、没有定位回退的流式文字，以及带描边的倾斜等部分变换仍会明确拒绝；脚本、事件代码、内部实体和外部样式资源也不能导入。遇到不支持内容时整次导入失败，并保留当前项目。导入最多 5 MiB，引用展开后最多 12000 个 XML 元素，单张图片单边最多 8192 像素，去重后总解码像素最多 6400 万。SVG 中的项目元数据不用于替代实际图形解析。格式差异、限制与回归运行方法见 [科研 SVG 兼容矩阵](docs/SVG_COMPATIBILITY.md)。

仓库的 `SVG_TO_JSON_TEST` 保留 6 张科研 diagram，包含 5 张已通过导入测试的图和 1 张已知因反射渐变被拒绝的工作流图；来源见 [SVG 样本清单](docs/SVG_SAMPLE_SOURCES.json)。运行 `npm run test:ui -- --svg-compat-only` 会测试顶层全部 SVG，并因保留的失败样本返回非零退出码。更多格式回归可运行不依赖外部样本的 `--svg-scientific-only`，详细运行方法见 [兼容说明](docs/SVG_COMPATIBILITY.md#运行回归)。

画板中的 **停止任务** 在生成时出现在工具栏；关闭生成设置窗口不会取消后台任务。失败后如出现 **继续未完成模块**，可在设置未变时复用已完成部分。编辑与局部重生成前，先确认当前结果已备份。

### 提交到论文

1. 完成画板编辑后，点击 **提交到论文**。
2. 在 **提交图表到论文** 窗口填写或确认图注，点击 **提交候选**。图名取自画板项目；该窗口不是图名或放置位置编辑器。
3. 回到 **章节编辑 → 图表与画板**，审核并 **接受并替换此模块**。
4. 再看全文预览。只编辑画板或只提交候选，都不会直接替换 PDF 中的已接受图。

后续可只修改图注，或再次编辑矢量对象。针对一张已有图提交并接受修改时，会保留其他图，不会因按钮写着“替换此模块”就删掉其余图。切换图或页面前应提交需要保留的改动，不要把浏览器自动保存当作项目主稿已更新。

### 导出和重新打开图

- **SVG 矢量图**：用于论文排版或其他支持 SVG 的工具。
- **JSON 可编辑项目**：用于在画板 **打开项目** 后继续编辑。
- **PNG 预览图**：用于查看或分享图的外观，不含可编辑对象。

已经有生成结果时，不必再次付费生图：找到对应的画板 JSON 再打开。`final-vector.png` 一类图片本身不能恢复文字、路径和分组；只有 PNG 时不能直接当作原生可编辑项目导入。

**论文项目 JSON** 与 **画板 JSON** 不是同一个格式：前者在工作台“导入项目”，后者在画板“打开项目”。

点击画板顶部 **关闭项目**，可选择 **直接关闭** 或 **导出 JSON 并关闭**。关闭会清空画板、材料和撤销记录，刷新后仍保持空白；服务器历史和论文中已提交的图表会保留。之后可重新打开 JSON、导入 SVG 或生成新图。导入或生成过程中，需等待完成或停止任务后再关闭。

## 8. 模板 PDF 预览与导出

### 全文预览

**全文预览** 展示后端按上传模板编译的真实 PDF，不是 Markdown 网页仿排版。保存正文、接受候选或更新模板后，预览随主稿更新；未接受候选不会进入 PDF。

可调整缩放、选择文字、点击 **打开 PDF** 或 **下载**。编译警告可展开查看；失败时检查提示并 **重试编译**。相同内容会复用缓存，编译 PDF 本身不调用模型、不产生模型费用。

当前仅配置英文 `pdflatex`。需 XeLaTeX/LuaLaTeX、中文字体、额外二进制资源或特殊目录结构的模板需要另行适配。更换模板不是无条件兼容所有会议样式。即使编译成功，仍需检查页数、浮动图位置、公式溢出、表格宽度与引用格式。

### 工作台“导出项目”菜单

| 选项 | 用途 | 包含什么 |
| --- | --- | --- |
| 可移植项目 · JSON | 备份、交接、重新导入工作台 | 材料、模板、模块主稿、候选、历史、引用、配置与原生图对象 |
| 全文 · Markdown | 继续编辑文本 | 当前已接受主稿的 Markdown；不替代完整项目备份 |
| 论文源稿 · LaTeX | 查看或编辑组装后的正文 | 单个 `.tex`；不包含全部样式与图形依赖 |
| 论文源文件 · ZIP | 在外部 TeX 环境继续编译 | `main.tex`、模板依赖、引用库、图的 SVG/PDF/JSON，以及项目 JSON、材料与 Markdown |
| 引用库 · BibTeX | 共享引用信息 | 当前结构化引用库 |

PDF 从 **全文预览 → 下载** 获取，不在上述菜单中。网页导出进入浏览器下载目录，不会自动出现在源码根目录。

建议同时保存论文项目 JSON 和论文源文件 ZIP：前者用于恢复工作台状态，后者用于外部排版。**论文源文件 ZIP 也包含原始研究材料和项目历史，不是可以直接公开的纯投稿附件**；公开前应另行挑选、审查文件。

## 9. 保存位置、备份与恢复

服务端把每篇论文按项目 UUID 保存，不按标题创建文件夹。默认数据目录如下：

```text
outputs/
├─ papers/
│  ├─ <项目ID>/
│  │  ├─ project.json          材料、主稿、候选、历史、引用与图对象
│  │  ├─ preview.json          当前 PDF 缓存索引
│  │  ├─ builds/<构建ID>/      main.tex、main.pdf、图文件和 compiler.log
│  │  └─ figure-jobs/          论文自动绘图的中间结果与检查点
│  └─ _runs/                  论文生成任务记录
├─ runs/<任务ID>/              独立绘图任务及检查点
└─ usage/                     模型用量记录
```

项目 URL 的 `?project=<项目ID>` 可帮助定位对应目录。**不要为了清理测试而直接删除整个 `outputs`**，这里包含正式论文与恢复数据，不是只有临时产物。

### 推荐备份方式

1. 保存正文编辑，提交并接受需要保留的画板改动。
2. 导出 **可移植项目 · JSON**，复制到自己的备份位置。
3. 需要外部编译时再导出论文源文件 ZIP；独立画板另存 JSON。
4. 恢复时，在工作台点 **导入项目**。它创建一个新项目，不覆盖原项目。
5. 换机器后配置自己的 API 连接，并重新绑定各模块与画板阶段；旧项目中的连接 ID 不等于新机器已有相同连接或 key。

如需备份整个本机实例，停止服务后复制 `outputs`。API 设置另在 `.local/api-settings.json` / `.env.local`，属于凭据，应单独安全保管，不能随着代码交接。画板也有浏览器自动保存，但清理浏览器数据、换浏览器或存储空间不足都可能影响它；不要只依赖自动保存。

## 10. 方法选择与新增方法

### 下拉框里的方法是什么

这些方法是本项目注册的 **adapter / pipeline**：方法声明适用模块和执行阶段，后端执行器读取项目快照并返回一个模块候选。它们不是模型名称，也不是自动发现或安装的 Codex `SKILL.md`。

一个方法可以是提示词、多个模型调用、工具调用或内部多 agent 流程。用户选择方法，系统执行所选流程；没有自动安装任意 GitHub 框架的功能。

### 当前正文方法

| 界面名称 / ID | 实际流程 | 使用注意 |
| --- | --- | --- |
| 证据规划 → 写作 → 修订 / `grounded-section` | 材料证据边界 → 写作 → 事实审查 → 至多两次定向修订 | 默认正文基线；不保证事实完全正确 |
| Orchestra · 章节写作 / `orchestra-section` | 适配上游章节提示词 → 单章写作 → 引用键检查 | 不是运行完整 PaperOrchestra |
| Evidence-first · 论证规划后写作 / `evidence-first` | 论点—证据计划 → 写作 → 独立审查 | 返回审查结果，不等同默认方法的自动修订循环 |
| Orchestra · 审查后修订 / `orchestra-refine` | 审查已有章节 → 定向修订 | 先要有章节内容；不是从空白开始的首稿方法 |

规划、文献和图表有各自的专用方法，只在支持的模块显示。整篇候选还会进行全局审查；它与单章方法中的审查不是同一个步骤。

### 想测试不同 Introduction 方法

不改代码：在 GUI 换方法、模型或修改要求，保留多个候选比较。为了比较方法而不是混合因素，应尽量固定材料、引用库、模型与上下文；改变上游内容后的旧候选不能用于等条件比较。

需要实现新流程时，主要文件如下：

| 文件 | 职责 |
| --- | --- |
| [server/paper/adapters.ts](server/paper/adapters.ts) | 方法注册、执行、现有写作流程与提示词；内置方法的执行器分发 |
| [shared/paper-methods.ts](shared/paper-methods.ts) | 内置方法名称、适用模块、阶段、来源和默认选择 |
| [shared/paper-types.ts](shared/paper-types.ts) | 输入、输出、方法定义、候选与项目类型 |
| [shared/paper-project.ts](shared/paper-project.ts) | 接受、依赖、锁定、历史等主稿事务；通常不因新增写作方法而修改 |
| [vendor/paper-orchestra](vendor/paper-orchestra/PROVENANCE.md) | 保留的上游提示词与出处；不要把它当成唯一扩展入口 |

建议在 `server/paper/` 新建独立执行器文件，再在 `adapters.ts` 注册 `registerPaperAdapter(definition, execute)`。声明新的稳定 ID、版本与 `modules: ["introduction"]`；执行器返回当前章节 Markdown 和警告，使用传入的模型调用与取消信号，不直接写主稿、不硬编码 key。

GUI 从 `/api/paper-methods` 读取注册表，正确注册后无需修改下拉框；只添加方法名称而未实现执行器，不会获得新流程。**实现前先读 [MODULE_CONTRACT.md](docs/MODULE_CONTRACT.md)**，其中有准确类型、两个文件位置的注册示例与交付约定。修改后运行测试与构建并重启。


`node_modules`、`dist` 是生成目录，不手动编辑或提交。`outputs`、`.local`、`.env.local` 是本机数据/配置，不能跟随公共源码。`archives` 是历史归档，不参与正常构建；源码包中不含这些私人目录。

各合作者独立开发自己的模块方法，尽量保持共享契约稳定。通过 Git 分支与 PR 合并代码；共享研究状态用项目 JSON。当前没有多人实时共同编辑，也没有自动合并两个独立修改的论文 JSON；建议约定一个主稿维护者负责接收修改。

### 生成干净源码包

在项目根目录执行：

```sh
npm run package:source -- --check
npm run package:source -- --name paper-studio-team --stage
```

输出到 `releases/`：源码 ZIP、SHA-256 清单和干净源码目录。同名目标不会覆盖，后续打包换一个名称。源码包不包含真实论文、实验结果、API 凭据、依赖、构建产物、私人验收记录或未获转载许可的参考图；合成 demo 随包提供。

在 GitHub 上传/创建仓库时使用干净目录的内层 `paper-studio/` 作为仓库根，保留隐藏的 `.github`、`.gitignore`、`.gitattributes` 和 `.env.example`。上传源码文件，不是把 ZIP 本身当作源码仓库。不要直接上传整个原始工作区。

打包器有凭据检查，但不能代替对未知秘密、研究隐私和第三方权利的人工审查。每人使用自己的 key。完整操作见 [GITHUB_HANDOFF.md](docs/GITHUB_HANDOFF.md) 与 [CONTRIBUTING.md](CONTRIBUTING.md)。

## 12. 配置项与测试

### 可选环境配置

日常 API 配置优先用 GUI。需要环境变量时，参考根目录 [.env.example](.env.example)，在本机创建不提交的 `.env.local`，修改后重启服务。不要在 README、源码或提交记录里填真实 key。

| 变量 | 默认 / 用途 |
| --- | --- |
| `PORT` | `8787`；后端监听端口 |
| `OPENROUTER_API_KEY` | 旧 OpenRouter 环境配置入口 |
| `OPENROUTER_TEXT_MODEL` / `OPENROUTER_IMAGE_MODEL` | 该兼容入口的模型 ID |
| `PAPER_REASONING_EFFORT` | 示例为 `high`；是否支持取决于接口与模型 |
| `SEMANTIC_SCHOLAR_API_KEY` | 可选 Semantic Scholar key，不是写作模型 key |
| `PAPER_PDFLATEX` | `pdflatex`，或本机编译器完整路径 |
| `PAPER_PROXY_URL` | 可选 HTTP(S) 代理 URL |
| `PAPER_SYSTEM_PROXY` | `1`；Windows 自动识别已启用的本机回环系统代理，`0` 关闭 |
| `PAPER_FIGURE_FONT` / `PAPER_FIGURE_BOLD_FONT` | 非 Windows 矢量 PDF 导出的可选字体路径 |

代理配置不能保证绕过供应商地区或账户限制。更换 `PORT` 后使用对应浏览器地址；开发模式的 `vite.config.ts` 代理目标目前固定 `8787`，还需同步调整。

### 检查代码与构建

```sh
npm run check
npm test
npm run build
npm run package:source -- --check
```

单元测试使用模拟服务，不调用付费模型。构建/回归通过验证程序行为，不代表论文内容或图像已达到投稿质量。

### 网页回归测试

```sh
python -m pip install playwright
python -m playwright install chromium
npm run test:ui
```

网页测试使用独立 `8788` 端口、合成材料、假接口和本次专属临时目录，不读取正式论文、不调用付费供应商；结束后清理测试目录。Windows 优先已安装 Edge，其他情况使用 Playwright Chromium。

可用 `PAPER_TEST_PYTHON` 指定 Python，可用 `PAPER_TEST_BROWSER` 指定浏览器可执行文件。默认包含 PDF 回归，需可用 `pdflatex`。没有 TeX 时，PowerShell 可显式跳过 PDF 测试：

```powershell
$env:PAPER_TEST_SKIP_PDF = '1'
npm run test:ui
Remove-Item Env:PAPER_TEST_SKIP_PDF
```

测试会报告 PDF 跳过，不能将其当成已验证模板编译。GitHub Actions 配置了 Windows / Node 24 的单元测试、构建和源码检查；上传后才会实际执行，不等于本机运行过网页测试或远程 CI 已通过。

## 13. 常见问题

| 现象 | 先检查什么 |
| --- | --- |
| 浏览器打不开工作台 | 确认终端中的服务仍在运行、地址端口正确；不能只双击 HTML |
| 启动报端口占用 | 先确认是否已有 Paper Studio 实例；不要盲目结束无关进程。停止自己的重复实例或更换端口 |
| 页面还是旧版 | 重新构建并重启服务，刷新页面；确认访问的是本次启动的目录/端口 |
| 提示 API 未配置或连接已移除 | 到 API 设置保存连接与默认值，再绑定模块；导入别人的项目不会导入其 key |
| API 返回 401 / 403 | 检查凭据、账户权限、供应商地区限制与实际服务端网络；以错误详情为准 |
| 模型不存在、图片生成失败 | 核对该供应商的模型 ID、命名方式、视觉/图片输出能力及兼容协议 |
| “测试连接”成功但生成失败 | 连接测试不调用具体生成模型，不能验证模型权限、额度或所有输出能力 |
| 文献检索失败或限流 | 检查服务提示，稍后重试、缩小检索要求或手动登记真实文献；不要用虚构引用补齐 |
| 生成了候选，但 PDF 还是空的/旧的 | 接受候选并保存编辑；全文预览读取主稿，不读取未接受候选 |
| 候选提示依赖已变化 | 查看是否手改上游、更新材料、恢复版本或用了其他批次；按最新基线重新生成相关候选 |
| 仅图表生成失败 | 查看运行记录，保留已完成正文；使用“重试未完成模块”，不必重做所有章节 |
| PDF 缺少 `.sty/.cls` | 在研究材料的模板入口补齐文件；上传完整模板而非只有示例 `.tex` |
| PDF 提示找不到 `pdflatex` | 安装并配置 TeX 环境，检查 PATH 或 `PAPER_PDFLATEX` 后重启服务 |
| 预览不是上传模板的样式 | 检查当前项目的模板、主文件与依赖；缺模板会用 article，特殊模板仍可能需适配 |
| 中文主稿不能编译 | 内置 PDF 仅配置英文；导出源文件，在支持中文的 TeX 环境中调整并编译 |
| 引用键未登记 | 在结构化引用库登记文献，并用库中显示的键替换正文 `[@key]` |
| 画板修改没进入论文 | 依次“提交到论文 → 提交候选 → 接受图表候选”，再预览 |
| PNG 导入后不能逐对象编辑 | PNG 没有原生对象；恢复编辑应打开对应画板 JSON |
| JSON 导入失败 | 区分论文 JSON 与画板 JSON；检查文件是否完整、来自对应导出入口 |
| 源码包里没有原论文或参考图 | 这是预期隔离；私人数据和无转载授权参考图不进入 GitHub 源码包 |
